# 公开仓库前的隐私检查

公开源码使用通用示例，不保留个人家目录、真实主机地址、会话或进程标识、私人项目名和私有报告路径。项目的公开仓库 URL 和第三方产品名继续保留。用途明确的合成 ID、回环地址、已说明的默认目录、协议字段和测试值可以保留。

历史检查记录分别说明已观察到的结果、失败的检查和未执行的工作。把标识改成说明性占位符，不会将失败改写为通过。记录提到的私有报告不随仓库发布。

## 分别检查文件和历史

对准备发布的文件运行：

```bash
python3 scripts/check_public_content.py
```

脚本只报告位置和类别，不打印匹配内容。它只能识别常见格式，不能发现所有私人项目名、短标识、部署备注、图片或凭据。查看结果后仍需人工检查源码。替换规则、原标识、原始报告和前后对应表保存在公开仓库以外。

工作目录干净，不代表 Git 历史已清理。检查全部分支和标签名称、提交及标签消息、作者/提交者/标签创建者信息，以及历史文件内容。reflog、旧历史备份、linked worktree 的 HEAD、运行时 snapshot/workspace refs、不可达对象都可能保留当前分支中已不存在的数据。

## 单独准备候选仓库

在私有、独立、与原仓库对象没有硬链接的镜像中改写历史。使用 `git-filter-repo` 等持续维护的工具，不修改共享原仓库的 refs、对象、index 或 worktree 登记。公开候选只保留明确需要的开发分支和发布标签；运行时恢复 refs 和旧历史备份仍私下保留。

匿名化身份时，`CLI Agent Bridge contributor (anonymized)` 和 `example.invalid` 地址是明确的占位身份，不代表已核实的真实作者。保留第三方署名和许可证说明，也不能根据占位身份推断已有贡献者许可。

改写历史会改变提交 ID 和附注标签的 ID。私下保存前后对应表，核对父提交关系和保留的标签名，并记录是否存在签名。改写后的原签名会失效；签名发布需要另行决定、重新签名和发布。版本名称相同，不证明旧发布包与清理后的源码相同。

改写后检查每个保留的 ref 及其历史对象，确认镜像没有指向原仓库的 remote、没有共享对象硬链接，并执行 `git fsck`。等最终检查过的源码不再变化后，再追加这份文件树，重新检查文件与内容。仅清理历史快照，不会自动带入后续修复或文档。

如果无法确认历史已清理干净，就用已检查的当前文件创建全新的公开历史起点，原历史私下保留。本地候选不等于已经发布，也不授权修改现有 remote 或强制推送。

## 历史重写之后继续工作

重写 Git 历史不会修改运行配置、状态备份或运行中的服务，这些内容需要单独维护。

把清理后的仓库克隆到新目录。旧目录中未提交的工作应私下保留，只转移已经检查过的文件改动，不复制 `.git`。不要合并旧分支或推送备份 refs，否则会把删掉的历史带回来。仍有活动 worktree 的共享副本应保留到工作结束，同时禁用其推送地址，后续修改使用新副本。

Release 附件、CI 运行的作者信息、构建包和缓存需要另行检查与清理，恢复用副本只保存在私有目录。完成后从远端重新克隆检查，并核对按标签下载的源码归档。服务器缓存的旧提交页面和其他人的克隆需要分别处理，仅重写分支不能证明这些副本已经消失。

## 限制

移除候选仓库中的数据，不能抹除其他克隆、远端缓存、fork、发布包、备份或已经发出的消息。已经泄露的凭据仍需单独撤销。不要发布运行数据库、认证状态、含密钥的环境文件、原始会话或屏幕录像，即使文件名看起来无害。
