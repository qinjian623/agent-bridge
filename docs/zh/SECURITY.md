# 安全说明

## 支持的部署方式

Bridge 面向单个操作系统用户及明确受信任的 SSH 主机。每个节点使用自己的 CLI 账号、文件、数据库和用户服务。Git worktree 或目录副本用于分开文件修改，不能阻止同一用户身份下的恶意工具或代码访问其他文件。不支持原生 Windows；请使用 Linux、macOS 或 WSL2。

Web 监控默认只监听本机回环地址。远程访问应使用经过身份认证的 SSH 隧道，或受信任的 HTTPS 反向代理，并明确配置允许的 Host 和公开 Origin。不要公开无需认证即可访问的代理，也不要向不受信任的客户端提供管理员令牌。浏览器 Cookie 和审批操作需要保留现有的 CSRF 防护。

凭据应保存在各 CLI 自己的认证存储中，或仅属主可读写的环境文件中。不要将令牌、运行数据库、任务聊天记录、原生会话日志或私人主机配置放入本仓库、issue、截图或 PR。模型输出、补丁、仓库内容和外部消息都应按不可信输入处理。

升级前备份私有状态目录并阅读发布说明。文件校验和可以发现下载损坏，无法防止发布者账号被盗后提供恶意版本。操作结果不明时保留现场并检查，不要盲目重试可能已生效的操作。暂停或关闭的主会话不会被自动唤醒。

分享仓库、发布文件或检查报告前，请阅读[隐私与公开检查](privacy.md)。

## 报告漏洞

如果本仓库已启用 GitHub 私密漏洞报告，请使用 **Security → Report a vulnerability**。如果没有启用，可创建 issue 请求私密报告渠道，但不要附上利用细节、凭据、私人路径或聊天内容。不要在公开 issue 发布可直接利用的攻击示例或密钥。

报告应包含受影响版本、操作系统、部署方式、使用虚构数据的最小复现步骤，以及预期和实际行为。本项目没有约定的响应时限。修复通过新版本发布；请部署经过检查的最新版本，不要假定旧版本会收到修复回补。
