# 2026-11-08 Notification and Wait Fixes

Based on findings from an external coordinator stall investigation report (`<private-investigation>/REPORT.md`): five historical notifications were queued in the afternoon and entered native turns later that evening, while the first four had already been ACKed earlier in the afternoon. The six-hour stall occurred inside the primary Codex client's own model request phase rather than blocked unreturned Bridge child tasks.

## Notifications

- When notifications remain in the native queue, an `active/idle` parent thread no longer produces `ready=true`. Only matching the native `userMessage.clientId` records `native_status=received` and `native_turn_id`; this proves native turn admission rather than confirming model comprehension.
- `parent_ack` records coordinator processing (`status=processed`) and may originate from independent `agent_result` handling without falsely rewriting native send status to `received`.
- After ACK, `queue_cleanup=pending` is persisted, and background retraction locates only that exact `(thread, clientId, receipt)` entry. Missing receipts recover only from an unambiguous unique `clientId` match—never matching by body text, clearing the whole queue, or evicting unrelated items.
- Still-queued items can be retracted; items already admitted into a native turn record `already_started` without rewriting history or interrupting active turns. Paused or closed parent records do not block retraction, and retraction never calls `enqueue`, `resume`, `steer`, or `interrupt`.
- Lost delete responses, `deleted=false`, conflicting receipts, or missing delivery proofs keep `uncertain`; subsequent checks inspect queue/turns read-only without repeating deletes. Pre-delete connection/lookup failures keep `pending` for safe retry.
- Concurrent ACK and send responses preserve late receipts without letting stale sends or cleanup overwrite newer `removed`/`received` facts. Cleanup claims are checked before mutating native send state.
- Legacy `accepted` records are re-verified read-only rather than treated as read proof; legacy `processed` records preserve ACKs while inspecting up to the most recent 100 native turns (remaining unknown beyond window bounds without resending).
- Normal startup repairs `processed + queue_cleanup=NULL` left by mixed old-broker / new-worker transitions without resetting existing terminal cleanup states.
- Notifications embed event timestamps and explicitly state they do not authorize resuming paused development or re-running tasks.

`deliveries` adds `native_status`, `native_turn_id`, `queue_cleanup`, and `cleanup_last_attempt` while preserving all existing APIs and status fields.

## Bridge Child Task Waiting

- One deadline in `JsonProcess.request()` now governs both stdin writing (including previously unbounded `stdin.drain()`) and response waiting. Timeouts record method and `write`/`response` stage, clear pending waiters, and never resend requests.
- Worker startup continues using `task_timeout`. Stalled connects stop waiting while leaving undispatched tasks `queued` rather than auto-restarting tasks.
- Task timeout, pause, or cancellation prior to native admission terminates wait loops cleanly; tasks with unconfirmed execution become `recovery_needed` and pause follow-on dispatches rather than claiming cancellation.
- After native admission, normal interrupt flows and `interrupt_timeout` apply and require terminal confirmation. `native_wait_ended` records stage and cause without changing models, approvals, or local timeouts.

These changes do not resolve client-side six-hour model HTTP stalls inside external Codex CLI requests (which require client-side phase logging across send, headers, stream idle vs. total deadline; note `stream_idle_timeout_ms` covers only SSE chunk gaps per [OpenAI Config Reference](https://learn.chatgpt.com/docs/config-file/config-reference)).
